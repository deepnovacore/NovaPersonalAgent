# 设置

从悬浮球菜单打开设置。桌面设置按用途分组：

| 分类 | 内容 |
|---|---|
| 通用 | 语言、启动视图、唤醒词、通知、意图澄清、主动发现和显示 |
| 简报 | 早晚简报及免打扰时段 |
| 主题 | Nova Visor 桌面信息层和悬浮球外观 |
| 用量 | 本次运行和累计用量，以及费用估算 |
| API 密钥 | ChatGPT/Codex 登录和模型服务商凭据 |
| 模型 | 文字与语音模型、一体式或级联语音、语音识别与合成 |
| 技能 | 已安装技能及技能目录 |
| 执行器 | 视觉与编码执行器、执行器配置和工作区 |
| MCP | MCP 服务及开放的工具 |
| 连接器 | 即时通讯渠道、授权资料来源和已连接应用 |
| 设备 | Space Host 设置和已配对的 Client |
| 权限 | 桌面系统权限与审批控制 |
| 隐私与数据 | 将对话内容发送给模型服务的授权 |
| 知识库 | 导入文档、向量模型、存储和检索 |

## 保存与重启

保存后，界面会提示修改已经生效，或需要重启后端。外观、新会话的默认执行器等设置无需重启；模型、能力开关、MCP 和连接配置可能需要重启，以界面的待重启提示为准。

替换受支持的服务商密钥时，如果后端已建立对应客户端，且旧密钥没有被其他配置共用，就可以直接应用到正在运行的后端。新增、清除、修改共用密钥，或修改尚不支持即时替换的凭据，需要重启。密钥只写不读：界面显示是否已配置，不显示保存的值。由 `.env` 管理的凭据应在该文件中修改。

重启会使用已保存的设置，并保留未发送的草稿。如果配置导致启动失败，可以从界面恢复上一次可用设置。

## 本地 Build 审批

输入框上的审批控件可在「总是询问」和「总是批准」之间切换，适用于本地 Build 的文件写入、编辑和 shell 命令。修改从下一次工具调用起生效，并在下次启动时沿用。它与编码执行器自身的审批策略分别设置；直接启动 runtime 时可使用 `NOVA_LOCAL_TOOL_APPROVAL`。

Computer Use 还需通过平台、模型、显示器和系统权限检查。打开它不会自动授予缺失的操作系统权限。Plan 和 Build 的语音会话不提供工具，执行操作须回到文字会话。

## 技能与用量

技能位于 `~/.nova-personal-agent/skills`，每个包含可读 `SKILL.md` 的子目录对应一个技能。首次运行会补入 Computer Use 技能，但不覆盖已有的 `SKILL.md`；修改目录后刷新技能面板即可。

用量中的费用是估算值，部分外部工具不回传用量，因此不能把它当作完整账单。
