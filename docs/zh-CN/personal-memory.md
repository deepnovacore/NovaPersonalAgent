# 个人记忆

主动发现、动态、时间线、简报和画像依赖 Nova ledger 权威底座；底座上的召回引擎可选 ledger、mem0 或 VoiceMem。旧独立 mem0 与远程资源不因此获得账本产品能力。配置与回退说明见[配置指南](configuration.md)。

启用非账本产品记忆资源（如旧独立 mem0 或 remote）时创建的任务结果动态，会持久保存 `memory_origin: 'non_product'` 标记。它们仍可在本地查看，但不会进入发送给模型的主动发现、简报、时间线、建议选择或语音播报；重启或切换到账本后也不例外。完全未配置记忆资源时，新任务结果不带此标记，仍可用；不带标记的旧任务结果也不受当前记忆后端限制。依赖记忆的动态必须通过产品底座；未启用产品底座时，仅引用证据的动态须由非记忆来源独立解析证据。App 记录引用（如待办、目标和任务）不要求记忆后端；所有发送给模型的用途都会重新校验其当前版本与目标访问权限。关闭记忆不会让无法解析的记忆证据变得可用。

定时任务摘要在投递动态前持久保存可选、枚举受限的 `memory_origin: 'non_product'` 字段，并复制到动态及聊天气泡。投递重试会保留生成时的来源标记，不受后端切换影响。这是增量兼容的结构变更：旧摘要无需改写，仍不带标记。

使用 App 上下文生成的回答、带版本的计划和 Plan/Build 检查点，会保留可选且有上限的 `context_dependencies`，并继承先前回答的依赖。重用历史或语音上下文前必须重新授权；依赖超限时整体不可用于模型，不会截断依赖后放行。旧记录仍可在本地查看；无法验证来源的旧 App 派生检查点会拒绝模型重用，但不会删除计划或工具回执。确认计划后的交接会保留该发布版本的依赖，并在模型使用前重新校验接收方。个人语音通知即使经过发言等待或重连，也会在实际注入服务商前重新授权。无关的独立会话仍可使用。

Nova 会从对话中整理信息，方便你在之后的会话中继续提问。个人记忆默认开启，使用本地统一账本保存，支持对话回忆、来源依据、纠正与忘记。也可显式选择 mem0。

## 怎么使用

直接告诉 Nova 一条信息，例如：“我的示例项目叫青杉，编号是 C-731。”稍后在新的会话中问：“青杉项目的编号是多少？”

整理记忆需要时间，刚说过的信息不一定立即出现在记忆中。你可以在桌面查看学习状态。

默认本地账本还支持明确保存：例如“请记住叫我 kant”。Nova 通过 `memory__remember` 同步保存事实或偏好，收到成功回执后才确认；新对话可以立即读取，重启后仍保留。称呼仅作为称呼偏好，不代表法定姓名。你也可以明确要求改称呼或忘记这条记忆。

称呼和回答风格优先进入对话上下文。其他明确保存的事实可通过 `memory__lookup` 分页或按条目读取；历史信息可通过 `memory__recall` 用自然语言查找，并通过 `memory__evidence` 查看来源。后台自动整理仍用于普通聊天；有显式保存的那一轮以提交的条目为准，不再重复提取整句。保存失败或发生版本冲突时，不会确认保存成功；显式写入暂不支持旧独立 mem0 和远程后端；账本上的 mem0 / VoiceMem 召回组合保留该能力。忘记会隐藏条目及该次保存的来源。同一句原话保存的不同事实互不连带隐藏；但另一条保留事实的宽泛引文仍可能提到已忘记的信息。忘记不等于彻底的语义删除，也不会删除聊天记录。

记忆目录位于 `<MEMORY_LEDGER_PATH>.memory/`：`USER.md` 保存明确的个人信息，goal/todo/idea 各有独立文件，`MEMORY.md` 是生成的目录。Profile 概览仍由事实派生，不建立另一套事实存储。可编辑有标记的条目正文；身份、版本、来源、状态和关联由 Nova 管理，修改经过同一个版本合并流程。

## Plan / Build 中的记忆

Plan 和 Build 的文字会话可以使用当前后端支持的记忆检索工具；支持显式保存的后端还会提供 `memory__remember` 和 `memory__lookup`。两种模式都**只在用户明确要求时通过 `memory__remember` 写入**，不会自动学习。保存必须引用当前用户文字回合中的原话，并收到 committed 回执后才算成功；文件内容、工具结果和语音转写不能授权保存。这些规则属于每一轮 Workbench 的系统指令，恢复的会话也不例外。恢复执行沿用原始用户文字，不把宿主上下文当成新请求。

项目、代码和仓库约束使用 `scope=general`，仅用户本人的稳定信息使用 `scope=user`。通用项目记忆仍可通过 `memory__recall`、`memory__lookup` 和记忆页读取，但不进入 `USER.md`、语音的 “Memory facts” 事实列表或回答偏好；语音事实和回答偏好的 general 范围排除规则仅适用于 Nova 账本：远程后端和 VoiceMem 适配器的偏好不携带 scope。此排除规则不覆盖派生摘要。

新文字回合会在已授权的共享检索中尝试查找少量相关记忆，作为不可信参考上下文注入；约 400 毫秒内未完成或失败则跳过，不阻塞工作。重试或恢复时会丢弃待发送的检索上下文，重启后也一样；Resume 不会重新检索。这不依赖 `MEMORY_PRERECALL_ENABLED`，也不会触发自动写入。Plan / Build 的语音仅用于交流和引导，不提供任何工具，也不再自动捕获记忆；记忆写入请回到文字会话明确提出。Chat 语音的自动捕获行为保持不变。

## 查看记忆

[![主窗口中的个人概览](../../assets/features/profile-original.png)](../../assets/features/profile-original.png)

默认账本可在主窗口的记忆视图中查看、纠正和忘记条目。以下面板说明仅适用于旧独立 mem0 配置；该独立模式不启用依赖账本的来源连接器。

右键点击悬浮球，打开「记忆面板」，选择个人记忆。这里可以：

- 搜索你说过的原话。
- 查看已整理的信息，以及对应原话。
- 翻页浏览记录，区分「已学习」和「尚未形成记忆」。

搜索按原话匹配；内容较长时会显示节选。目前条目查看支持本地 mem0，面板暂不提供编辑和删除按钮。

## 数据存在哪里

统一账本默认保存在 `~/.nova-audio-agent/workspace-graph.sqlite`，可用 `MEMORY_LEDGER_PATH` 指定其他位置。旧独立 mem0 使用 `~/.nova-audio-agent/memory.sqlite.mem0/`，不同用户的数据分别存放；新的 SDK 召回组合继续使用账本，并另建派生索引。

**本地保存不等于离线处理。** 整理信息和生成检索向量会调用你配置的模型服务，并向该服务发送相关文本。

个人记忆与文档知识库分开：前者来自对话，后者来自你导入的文件。记住一条信息不会授予 Nova 执行任务的权限。

## 更改或关闭记忆

源码运行时，在 `.env` 中配置后重启 Nova。默认配置无需填写。

| 选择 | 配置 |
|---|---|
| 本地统一账本（默认，含旧数据迁移） | `MEMORY_CONNECTION=local`，引擎及 provider 变量均留空 |
| 显式账本组合（无旧数据迁移） | `MEMORY_CONNECTION=local`、`MEMORY_RECALL_ENGINE=ledger`、`MEMORY_EXTRACTORS=ledger` |
| 独立 mem0（已弃用的选择方式） | `MEMORY_CONNECTION=local` 和 `MEMORY_PROVIDER=mem0` |
| 关闭个人记忆 | `MEMORY_CONNECTION=disabled`，移除 provider 配置 |
| 连接远程记忆服务 | `MEMORY_CONNECTION=remote`，配置下述地址和令牌，移除 provider 及两个新组合变量 |

`MEMORY_PROVIDER` 已弃用：旧 `voicemem` 保留默认账本迁移，旧 `mem0` 保留独立模式；不能与新变量共用。

远程服务需要 `MEMORY_URL` 和 `MEMORY_TOKEN`。服务须兼容 Nova 的记忆接口；不能直接填写任意 mem0 服务地址。远程连接失败时会显示不可用，不会自动改存本地。

统一账本可只读迁入旧 VoiceMem 记录，并保留原数据库。旧独立 mem0 不迁移账本数据；新 SDK 召回引擎可从现有账本回填派生索引。关闭记忆不会删除已保存的数据。更多配置见[上手指南](configuration.md)。

### 独立 mem0

mem0 支持回忆、用户原话证据，以及记忆页面的列表、更正和遗忘。显式 `remember` / `lookup` 工具仍仅由 ledger 提供。模型读取同时要求来源接收时保存的目标模型授权和当前配置授权；缺失授权时拒绝读取。升级前接收的数据仍可在记忆页面查看，但以相同来源 ID 重新接收完全相同的用户消息前不会提供给模型。仅刷新空授权快照；已有非空授权和已遗忘来源不会扩大授权。

更正以 SDK 条目 ID 为键持久保存本地覆盖内容。版本令牌由 SDK 更新时间与规范内容的哈希生成；无更新时间时回退为内容哈希。规范内容不超过 500 字符。更正或遗忘条目后，该来源不再重新提取，避免 SDK 分配新 ID 后恢复旧事实。原文证据始终是用户原话，不是更正内容或提取结果。遗忘来源立即写入墓碑，并在重启后继续清理衍生条目。更正只改变返回内容，不更新 SDK 向量，因此检索排序仍依据原向量。

mem0 列表每页扫描 SDK 存储一次（O(n) 读取、O(n log n) 排序），批量读取本地覆盖内容，仅构建当前页条目，不跨请求缓存扫描结果。不支持 `include_expired: true`，传入时返回输入无效错误；已遗忘条目始终不列出。

### 高级后端组合

`MEMORY_RECALL_ENGINE=ledger` 与 `MEMORY_EXTRACTORS=ledger` 显式选择 Nova 账本。
也可选择 `MEMORY_RECALL_ENGINE=mem0|voicemem`，并以 `MEMORY_EXTRACTORS=ledger,voicemem` 显式增加短期风格抽取；它不写成账本事实，默认不开启。`MEMORY_PROVIDER` 已弃用：旧 voicemem 保留账本迁移，
旧 mem0 保留独立模式。新旧变量不能共用，新变量不能覆盖远程连接的引擎。
显式选择的召回引擎不会被静默替换，也不会默认启用。设置界面没有引擎选择器。
支持的选择方式见[配置指南](configuration.md)与[记忆架构](archs/02-memory.md)。
