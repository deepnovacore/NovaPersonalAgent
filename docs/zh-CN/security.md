# 安全与隐私架构

Nova Personal Agent 围绕“本地宿主权威”与“显式权限边界”设计。

## 1. Space / Host / Client 加密边界

- **Host 持有权威数据与密钥：** Space 私钥、内容加密密钥、模型 API 密钥以及全部个人数据仅保存在 Host 本地（`0700` 私密目录）。
- **Relay 零知识转发：** `relay` 仅在 Host 与已配对 Client 之间转发端到端加密（E2EE）密文，不运行 Agent，也无法解密用户内容。
- **推送网关元数据边界：** `push-gateway` 仅接触通过 APNs / FCM 唤醒设备所需的设备令牌、发送时间与密文大小。
- **配对校验：** 设备配对通过一次性二维码与 Host 端完整设备指纹比对确认后，才会下发内容密钥。

## 2. 来源读取与模型处理分离授权

- 连接本地文件夹、邮件、日历或飞书仅代表授予**本地读取权限**，不代表自动允许将内容发送给外部模型。
- **允许模型处理**需要单独的显式授权。记忆条目与检索文档在模型上下文中始终被视为**不可信数据**，不能覆盖宿主权限控制。

## 3. 个人记忆可控性（溯源、遗忘与清除）

- 统一账本（`workspace-graph.sqlite`）中的每条记忆均保留来源出处与修订历史。
- 执行遗忘或撤回同意会立即写入墓碑，并通过事务队列同步清理派生召回索引（`mem0` / `voicemem`），防止已删除事实再次进入上下文。

## 4. 执行器与界面操作审批门控

- **编程与 Build：** 新建或切换工作区、文件修改与命令执行均受宿主状态机与审批门控约束。
- **Computer Use 与 Mobile Use：** 桌面与手机界面操作需要显式的会话准入与操作级审批；截图仅作为所有者可见的本地私有产物保存。
- **安全漏洞反馈：** 参见 [SECURITY.md](../../SECURITY.md)。
