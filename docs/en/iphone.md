# Use Nova on iPhone

Talk to Nova, approve operations and receive task results on your iPhone. Models, memory and coding tasks run on your computer.

## Prepare

Have Nova working on the computer, connect both devices to the same Tailscale network, and install the iPhone client. Allow microphone access when needed. Keep the computer online.

## Pair

[![Nova iPhone client and connection settings](../../assets/features/iphone.en.png)](../../assets/features/iphone.en.png)

On macOS, right-click the orb and choose “连接 iPhone…”:

1. Enable the phone connection.
2. Follow the secure-connection prompts.
3. Scan the QR code on your iPhone and confirm the connection details.

Codes are single-use; refreshing invalidates the previous code. You can revoke paired devices on the computer. For a separately hosted service, see [remote deployment](deployment/remote-server.md).

## Talk or type

Realtime conversation is the default. If the computer uses cascaded speech and supports editable input, text chat is also available. Type a message or dictate, edit and send a draft.

Switching to text pauses live audio. Switching back cancels ongoing dictation but preserves the text draft. Changing the phone's view does not change the computer's voice pipeline.

## Tasks and permissions

Tasks execute on the computer. When approval is needed, the phone shows the operation and the available decisions. “Allow” applies only to that request; “Allow for this session”, when offered, keeps the grant for the rest of the session, so choose it deliberately.

Ending a call does not cancel a task; request cancellation explicitly. After reconnecting, use the returned task state to check progress instead of repeating an approved operation.

## Limits

The message list may not survive an app restart. Phone cameras, screen sharing and background wake words are not supported. Network conditions, computer sleep and audio permissions affect calls. Reconnection clears stale audio and approval controls; approvals are not replayed automatically.

The supported iPhone app is the native client in `clients/ios/Nova`. The Flutter client in `clients/flutter` (a five-tab workbench for Todos, Ideas, Goals, Feeds and Profile) is an in-progress port; it is not part of the 0.3.0 release, and Android, physical-device sync and live audio are not yet accepted.

For client integration, see the [protocol reference](protocols/client-v1.md).

## Flutter standalone local memory

In the Flutter client’s standalone Space, explicitly ask Nova to remember a short fact or preference. A save must quote the current user message verbatim (in direct voice, a verified final transcript); Nova should confirm saving only after a committed tool result. There is no automatic extraction. Local recall uses word overlap, not embeddings. Up to 200 active entries of 200 characters each are kept across restarts; a full store refuses new entries rather than evicting old ones. A bounded, data-only summary is supplied to chat and voice. Ask in text chat to recall or forget an entry: forgetting erases its ledger text and quote and retains a tombstone, not the user's own conversation messages. The user's typed messages and spoken transcripts remain conversation history and are not erased by forget. Memory-tool arguments and results are stored only as redacted metadata; legacy memory-tool payloads are redacted when conversation storage opens.

Direct voice offers recall and save when its provider supports tools; forgetting is available in text chat. Forget gives each live memory consumer up to five seconds to invalidate its context after committing the tombstone: other active chat rounds are cancelled, and cascaded voice clears its live history/receipts and refreshes its summary before continuing. Any utterance still in progress when forget occurs is discarded and may need to be repeated; the speaking floor and tentative turn/caption state are reset. Providers without context reset (including Qwen-family adapters) end the call instead; provider closure is bounded and does not wait for background native audio/presentation cleanup. Only cascaded voice expires consumed memory receipts after narration. Qwen-family adapters retain receipt payloads in their live call context with a 128-item lifetime limit; forgetting ends those calls rather than expiring individual receipts. Consumer failure or timeout is reported as a text-free `invalidation_warning` on the committed forget result; later ledger operations and Space reopening are not held indefinitely by listeners. This Dart-only store is separate from the computer: client mode continues to use host memory, with no local memory tools, merging or synchronization. Device acceptance remains separate from unit tests.

`local_memory.json` contains verbatim source quotes as well as saved text. On iOS, the app-owned per-Space Application Support directory is excluded from future backups before Dart/native access, and the flag is reapplied on reopening existing data. This boundary includes memory, pending/atomic snapshots, corrupt recovery copies, derived tool artifacts, **and conversation transcripts and the Space workspace**; it does not exclude unrelated user-selected files. The directory and existing descendants receive `completeUntilFirstUserAuthentication` file protection. Descendant migration is cached per filesystem root identity only after success, invalidated on forget/reset/Space change, and repeated after root replacement; root exclusion/protection is reapplied on every access without repeatedly walking the workspace. Dart memory temporary files and recovery copies remain under that protected root; protection inheritance for atomic Dart writes still needs iOS device verification. Native upload files explicitly use the same protection. Backup exclusion comes from the containing root, independently of individual file attributes. This permits bounded background transfers after the first unlock, not access before it. On Android, Dart Space data remains in `filesDir/spaces`; targeted backup rules exclude this subtree from cloud backup and supported device transfer. Native private stores already use `noBackupFilesDir`; `allowBackup=false` is retained. Consequently this local Space data is not available from a new device's backup restore; keep any intentionally exported copies separately. Platform/OEM backup behavior still needs device verification. These exclusions cannot revoke **historical backups**, exports, or copies already made elsewhere. Forget does not delete the user's own typed messages or voice transcripts, but it does erase memory-ledger text/quotes and invalidate derived live context.

Corrupt or unreadable memory storage stays unavailable and is never automatically replaced. Recovery requires an explicitly authorized developer call to `LocalMemoryStore.resetUnavailable()`; on iOS it first revokes native model transfers, then copies any original file byte-for-byte to a sibling `local_memory.json.corrupt-<timestamp>` before resetting. A native revocation error aborts reset without creating a copy or replacing the ledger. No UI or automatic path calls this method. Recovery copies may contain private text and remain inside the excluded directory.

Local memory is not a source for profile inference, delegated tasks or scheduled runs. Space changes remount the Flutter shell (`KeyedSubtree` in `space_root.dart`): it stops the old voice session and agent, then closes the old memory store, rejecting new operations and draining pending writes. Ownership is per app process (the Flutter Dart isolate), not an inter-process lock. Each filesystem-canonical ledger identity has one live store owner, including while unavailable or closing. Identity resolves parent symlinks (or the deepest existing ancestor for new directories) and folds case only on case-insensitive volumes; Apple volumes are treated conservatively as case-insensitive unless proven otherwise. Opening a second store while that owner is live fails closed (`available == false`), with an explicit “Local memory is unavailable” message and no reads, writes, reset or cleanup; close the rejected instance and open a new one after the owner retires. Reopening while the old owner is already closing waits for its queued writes to drain. Failed startup attempts close their memory store before Retry is offered. Temporary filenames are instance-unique. Failed writes attempt to remove their own pending snapshot; at open and after every forget, only the sole owner inside its idle write queue removes abandoned snapshots matching this ledger's exact filename/UUID scheme. Cleanup compares the same canonical identities and never deletes pending filenames registered by an in-flight writer in the isolate. Cleanup failures are reported without file contents. Store-close and blocked-write/reopen behavior are unit tested; a live device Space-switch/call teardown still needs device acceptance. Voice tool payloads are not written to session logs or transcript caches; only actual conversation transcripts and delivery-state metadata enter conversation storage.

Native iOS model transfers no longer write orphan `.result` files: there is no result-file reader or replay API. A live suspended Flutter turn can still receive its completion; file-backed background uploads retain their existing 180-second request / 600-second resource limits. A terminated turn's response is discarded, not saved for later recovery. Native cancel, Space change, and committed memory forget revoke affected `.request` files and legacy `.result` files. Unstarted requests first reserve a native nonce bound to the selected standalone Space/generation: at most 128 reservations, each valid for 60 seconds. Reserve sends no body and starts no upload; cancellation during reserve never sends the body. Request consumes a matching live nonce with no implicit fallback; expired/cancelled/old nonces cannot be reused, even if a request ID is reused. New request filenames include the nonce, so an old callback cannot own or delete a later same-ID request. These limits do not expire active/background uploads. Each request also needs durable generation/nonce ownership in a protected, backup-excluded `Application Support/ModelTransferAuthority` control directory outside the deletable Space root. Control files contain bounded active-request metadata only, never prompts, credentials or responses. Canonical real storage paths (case-folded only on case-insensitive volumes) share one authority; root replacement invalidates old ownership. A stable filesystem lock serializes cross-instance read/modify/write, and callbacks reread authority before parsing or delivery. Revocation is recorded and synced before artifact cleanup; a failed manifest replacement leaves a durable blocked marker requiring explicit Space invalidation/retry. Corrupt or inaccessible control storage fails closed and returns fixed errors, not successful cleanup. A completely unsuccessful barrier write is not an acknowledged revoke: repair storage and explicitly retry. New nonces replace unseen older same-ID incarnations; streamed deltas carry the nonce and Dart rejects mismatches. Terminal cancellation state is retired only after disk revocation succeeds; failed cleanup retains a text-free gate and refuses new admissions until cleanup succeeds, rather than evicting relevant cancellations. Native callbacks check request ownership before parsing, streaming or delivering; cancellation wins even against a late successful callback, a switch away and back, or restoration of a task whose request file was removed. Cleanup callbacks never recreate removed Space directories. Reconciliation removes abandoned request files while retaining live uploads; opening memory also removes legacy orphan results. Forget awaits native revocation before Dart cleanup/listeners; filesystem/platform failures are exposed as text-free `recoveryCleanupError` / forget-result warnings rather than silently reported as successful cleanup. Ordinary conversation history is not erased.

On the first upgrade to durable authority, unfinished pre-authority uploads are cancelled once with a fixed interrupted/retry outcome, and their request/result artifacts are removed best-effort. Bare old files are never adopted as permission to resume; their unsaved response cannot be recovered. Saved conversations, memory and workspace data are not deleted. Ordinary generation-backed background uploads still survive relaunch. Cancelling only a stream subscription also revokes that round's pending/active admission, without permanently disabling the reusable model client; a delayed reserve reply cannot construct or send its abandoned body.

Validation here is Flutter unit/widget testing plus a standalone Swift harness exercising the native transfer callbacks with host doubles, and Swift source/type checks—not an iOS app build or device verification. On devices, verify suspended/background completion, termination and relaunch, cancellation/forget and Space-switch races, removal of request/result artifacts, iOS backup-exclusion and file-protection attributes on fresh, existing and replaced directories (including atomic writes/recovery copies and migration retry), and Android cloud-backup/device-transfer exclusion. No simulator/app launch or golden update is part of these checks.
